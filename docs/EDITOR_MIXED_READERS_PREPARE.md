# Request-driven paired editor preparation

`editor_mixed_readers_prepare` composes the genuine sampler reader factory with
the copied paired activation owner. It requires an already established sampler
and an attached idle mixed editor binding. It does not establish masters, produce
a whole song or connect native PLAY to a device.

The controller installs the existing editor preparation barrier before the first
allocation or callback. Each validation call performs one construction phase or
a bounded validator step. Each batch step performs one factory transition or at
most 256 derived bytes. Original master precision and the literal scheduled frame
and clock window are preserved. Paula uses selective signed8 Chip copies; card
readers use the existing optional 8/16-bit cache and reservation contracts.

The two command registrations and thirty-two persistent reader registrations stay
internal. Callers receive controller-issued slot/serial references. CONTROL and
STOP resolve an exact positive ACTIVE key immediately before lowering; an
external queue key or a reused slot cannot authorize them. Actual enqueue success
transfers ownership and preserves its ticket even when an enclosing callback also
faults the controller.

The controller tracks at most thirty-seven ordinary and thirty-two separately
sized Chip allocations. Captured numeric source extents, complete callback
contexts, full workspaces and all live allocations guard external requests and
outputs before writable fault state. These guards include unused sample storage
and unpublished resources. Child-local ticket and receipt slots do not bypass the
complete external guard.

Between calls, fixed editor, project, sampler and input identities are checked
before former source tables are traversed. Changes must advance the editor
revision or sampler generation. Valid channel selection movement remains allowed.
Stale ownership drains through NULL receipts using captured handles and numeric
extents. The caller retains the fixed controls and callback contexts until
terminal close; stale tables need not remain readable.

An enclosing task-side fault calls `pt_mixed_activation_fail_closed` only while
the genuine activation allocation remains in the controller's exact ordinary
ledger. The seam latches failure and advances the existing fault serial. It makes
no callback, cancellation, ownership transfer or quiet claim. Final allocation
release publishes actual child consumption before user release/reentry, so the
seam cannot access a freed owner.

The independently invoked activation fire still uses only copied packet values
and the original clock/commit callbacks. The controller's clock and commit
forwarders never inspect editor tables. Task-only publication and quiet wrappers
check fixed callback state while preserving the callback's actual raw reply.

Command detach, reader retirement and final callback-source quiet are separate
proofs. Edits, undo, route mutation and disposal remain vetoed while any submitted
or uncertain reference survives. Cancellation stops only unfinished factory work
and the unpublished local queue; it issues no musical STOP or device poll.
Cancelled untransferred reader handles close before their command handles. All
handles and the factory pool close before the activation owner. Actual close0
with a NULL child slot is terminal for that child, and an explicit later close
may still be needed to drain the editor hook. Pending source shutdown retains the
hook and contexts after the pool has gone. Only complete consumption clears it.
