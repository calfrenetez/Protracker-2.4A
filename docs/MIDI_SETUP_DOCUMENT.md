# Optional MIDI setup lifetime in document actions

The existing typed document action/replacement has an optional MIDI lifetime
composition for HOST qualification. It requires
`PT_DOCUMENT_MIDI_SETUP_HOST_ONLY=1` and the existing HOST-only setup-owner gate,
which still rejects native targets. Default builds leave this MIDI composition
disabled. An opt-in NULL owner/capacity0 follows the ordinary path.
This does not bind a native requester, activate MIDI, or add another document
producer, output owner or change barrier.

The typed admission checks the genuine original owner, exact full constructor
capacity, original editor identity, actual child binding and absence of a modal
borrow/draft. It is callback-free and writes no owner or caller output. Storage
spans must avoid the full sidecar, workspace and captured allocator/context.
An explicit context-input role permits only the exact complete captured context
as a shared input; a subspan/superset cannot grant overlap. Mutable action and
replacement control containers remain storage. Writes over even that shared
context are always refused. A numeric storage exclusion is safe after disposal
because it does not traverse the former editor/project/history. These are
negative checks, not quiet/closure or a complete heap/record-span census. Original
placement, fresh aligned disjoint allocation and source-lifetime contracts remain.

Preparation and PREPARED cancellation preserve the real MIDI journal, including
undone redo. The genuine replacement enrolls the optional owner before its first
step. It checks admission again on WAITING continuation and after real stop and
voice-close callbacks, immediately before irreversible editor disposal. After
actual disposal drains the journal, it attempts genuine MIDI-controller close
once, before phase2 can release the old document or publish its candidate. A
refusal latches HOLD without retry, forced clear or old-state restoration.

Only after genuine publication, final-address editor initialization and restoring
the original sampler allocator/budget does the replacement attempt fresh owner
rebind once. A failure retains the published document in HOLD. The owner,
workspace and original context remain alive through genuine finish; final close
and workspace release remain explicit owner operations. Existing finish still
requires final new engine/cache/editor retirement. Repeating native New/Load
remains unfinished. Source/song allocation policies are a separate contract. The
subsequent typed
replacement policy fix now preserves source capacity and custom song policy;
its loaded-source cases remain separate from this MIDI lifetime qualification.
See [source and song policy](DOCUMENT_REPLACEMENT_POLICY.md).
