# Classic MOD preflight and loader audit

19 September 2026. `PTModCheck` is a separate read-only tool backed by a portable,
allocation-free C validator. It is **not wired into ProTracker yet** and does not
protect the unchanged 2.3F baseline loader. The known-good baseline remains pinned.

## Source finding to address before broader file fuzzing

In pinned `vendor/pt23f/PT2.3F.s`, `SONG_SIZE_100PAT` allocates 1084 + 100 * 1024
bytes. `LoadModule3` reads a header without checking the returned byte count.
The `M!K!` path enables 100-pattern mode; `DoStartModLoad` scans all 128 order
entries and calculates a pattern read size from the highest byte plus one.
The clamp to 64 patterns only applies while 100-pattern mode is disabled.

Consequently a malformed `M!K!` with order value 255 and enough file data asks
DOS to read 256 * 1024 pattern bytes into 100 * 1024 bytes of pattern storage.
The excess is 159,744 bytes. This is a source-level bounds violation under those
conditions, not an emulator-observed crash report. No malicious file was loaded
into the unchanged tracker and no hardware reproduction was attempted.

Other audit points: the initial load clears the current song before the file is
validated; pattern and sample `Read` return values are not checked here. Loop
validation later uses word arithmetic and historically repairs some old files.
Review those compatibility choices before replacing them with strict rejection.

The next native hardening change needs validation before replacing the current
song, exact read checks, bounded pattern/sample allocation, and transactional
failure behavior. It must retain explicit legacy/packed-format paths rather than
reclassify unknown signatures silently. Emulator tests of that integration are
pending exclusive emulator availability and the implementation itself.

## Implemented validator

Supported preflight subset: 31-sample, four-channel `M.K.` (up to 64 patterns)
and `M!K!` (up to 100), matching the pinned editor's normal modes. This is not a
claim to recognize every MOD dialect. 15-sample modules, other channel markers
and packed files return unsupported; future importers must dispatch explicitly.

Checks include header length, 1–128 song positions, all 128 order entries,
complete pattern/sample storage, 31-instrument event bounds and widened sample
length arithmetic. Considering inactive orders matches the native sample-offset
calculation. A successful result reports byte offsets, required length and
warnings without changing the source. Failed validation leaves output untouched.

Warnings preserve, rather than repair, excessive volume, noncanonical finetune,
out-of-sample active loops and trailing bytes. Trailing metadata must not be
silently discarded. These warnings do not certify safe playback of a malformed
file by the old loader. This tool does not validate replay-effect semantics.

```sh
make modcheck
build/host/PTModCheck path/to/module
python3 tools/test_mod_corpus.py
sh tools/test_mod_fuzz.sh
AMIGA_CC=/path/to/m68k-amigaos-gcc make modcheck-amiga
```

CLI exit codes: 0 structurally accepted/no warnings; 5 accepted with warnings;
20 rejected or I/O failure. The CLI caps its whole-file buffer at 16 MiB; the
reusable validator does no allocation. A future in-app streaming loader should
avoid duplicating large sample buffers on constrained machines.

## Evidence

- Ten host unittest groups pass overall. C tests run with ASan/UBSan and cover
  every header/pattern truncation boundary, sample truncation, inactive orders,
  64/100 limits, instrument bounds, loops, maximum sample lengths and unchanged
  output on rejection.
- [Fifteen original synthetic corpus cases](../evidence/mod-preflight/corpus.json)
  pass through the host CLI. Fixtures are generated by
  `tools/make_mod_corpus.py`, with hashes retained. Malformed fixtures are for the
  preflight tool only until the tracker is hardened.
- [200,000 deterministic mutations](../evidence/mod-preflight/mutations.log),
  fixed seed `0x24`, complete under ASan/UBSan using exact-sized allocations.
  Apple clang's libFuzzer runtime is absent locally, so this is a deterministic
  mutation run, not a coverage-guided fuzzing claim. `tests/mod_fuzz.c` remains
  available for a compiler installation with libFuzzer.
- Native 68000/soft-float cross-build: 16,024 bytes. Compiler, runtime archive
  digests, inputs and binary digest are in
  [the build manifest](../evidence/mod-preflight/build.json).
  Native execution is NOT RUN; AmiConnect currently has exclusive emulator use.

Remaining acceptance: integration into a derivative loader, emulator rejection
with the previous song preserved, low-memory and partial-read injection, safe
save behavior, PP20/15-sample compatibility, and replay/effect traces. Passing
this preflight suite does not satisfy those separate gates.
