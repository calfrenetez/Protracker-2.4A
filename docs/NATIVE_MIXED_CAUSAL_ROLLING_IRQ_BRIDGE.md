## Separate normal-task delivery gate — 16 October 2026

`src/native/prepared_delivery_gate.c` supplies a smaller, separate ownership primitive for the next native integration. It has four numeric, single-use mailboxes and distinct task/local entry and restoration anchors. Each admitted entry owns one matched Exec `Disable`/`Enable` pair. Before calling `Enable`, the active entry ends while its restoration anchor remains. A local ordinary-C model delivery can complete during task restoration without a later whole-state rollback erasing its record. The original token object, generation and serial must match; copying a token transfers no entry authority. Stop blocks new staging while preserving old delivery and observation. A nesting or own-call identity anomaly retains faulted anchors without a speculative `Enable`, retry, reset or disposal.

This first API is restricted to a genuine original normal-task call path and local ordinary C. It must not be called from a real IRQ, Exec Cause/software interrupt, exception, supervisor or signal path. Task identity is only a cross-task check. Exec `Disable`/`Enable` return no saved SR/IPL token, and equal `IDNestCnt` values do not prove arbitrary original CPU state restoration. This restriction is a gate contract, not a claim that Exec forbids `Disable` inside interrupts. The gate performs no allocation, PCM/project traversal, pin/cache retention or release, clock acquisition, output, timer operation or source-quiet certification. Existing native provider `#error` barriers and the bridge's unconditional INVALID entry remain unchanged.

One HOST group passed; these are fixture scenarios, not a native IRQ, timing, source-lifetime or playback qualification.
