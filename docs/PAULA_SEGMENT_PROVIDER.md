# Typed serialized HOST provider

The adapter owns four once-only big-endian model records while preserving each original ticket, window and frame. Its explicit label table uses model numbers; these numbers are not native addresses and cache_base32 is never interpreted as a HOST pointer.

Injected resource callbacks provide modeled enter/restore, clock, packet, ticket, reader quiet and source quiet operations. Whole-entry serialization forbids callback reentry, including during restore. Packet quiet, reader quiet and source quiet are independent obligations. Unknown callback or restoration results latch failure and retain storage; observed returned entry tokens do not grant restoration authority. Original packet and genuine owner storage remain live through the required quiet proofs and positive outer restoration.

Known resource-context, descriptor, master, cache and guard extents are excluded from all caller outputs, including before a first record is published and after record retirement. This covers status, row, enter-token and clock outputs without treating the model label table as host addresses. The HOST75 fixture includes 45 genuine alias designs and verifies unchanged refused outputs, no provider effects and preserved ownership.

The exact V4 private HOST75 compile and fixture passed with C99, assertions, warnings as errors, AddressSanitizer and UndefinedBehaviorSanitizer. The formatting-only V4 successor preserves the earlier compiler-only V3 failure as separate history. The renamed packet32 donor main is not invoked, so this fixture does not claim its separate46-case suite or the future60 suite.

The canonical provider and its exact75-case fixture also passed once under the same strict sanitizer flags. The on-disk strict driver keeps ROOT_ADMITTED and FUTURE_HOST_QUALIFIED false and the future acceptance pin empty; the trial used separately reviewed ephemeral admission and the exact previously qualified future prerequisite. No frontend, PLAY default, general song scheduler, retiming or jitter policy is added.

Native builds remain inhibited. The HOST contract refuses delivery reentry during restore, whereas the older rolling IRQ seam permits deferred delivery on restoration. A real serialization and mutation seam still needs an explicit implementation and qualification; no casts bridge these contracts. Amiberry, A1200, hardware timing, audio and listening acceptance are not established by this HOST result.

## Refuse stale borrowed packets before resource entry

The provider now compares every still-borrowed packet with its retained complete
snapshot before asking the resource backend to enter another TASK or delivery
operation. An observed mismatch latches failure and returns without invoking
`enter`, publishing a token, altering caller packet bytes or granting cleanup.
The retained records, original-packet obligation and genuine source pins stay
live. Argument/output-alias refusal still precedes this state change. The check
reads at most four live packet snapshots and does not scan PCM or cache payloads.

The regression reproduces the former behavior: after an accepted packet changed
between entries, the resource enter callback ran and failure was detected only
afterward. The revised provider refuses before that effect. Twenty-four cases
cover twelve metadata changes in both TASK and delivery entry, including invalid
source counts and descriptor pointers that must never be followed. All resource
callback counts and the backend token/lock remain unchanged; output tokens and
changed caller packets are preserved. Each provider retains its record, and the
extension's genuine source owner keeps all three pins and2304 Chip-cache bytes.
No independent quiet or source release is manufactured by the refusal.

The current private committed export passes135 cases: the original75, the
previous36 callback faults and these24 entry cases. Its37 strict C99 units and
95-body/include closure run with assertions, ASan and UBSan. Baseline assertion
failure and both passing observations are preserved separately; the final oracle
spells out that arbitrary holder and source mutation remain unqualified. The
private classic baseline and all16 unrelated live paths were checked. Shared
guard bytes were unchanged throughout, and no service or target was started.
See [the scoped HOST evidence](../evidence/enhanced-editor/paula-provider-stale-entry-host/result.json).

This adds observation of changes to already-borrowed packet metadata before a
new operation. It does not authenticate current master versions, detect arbitrary
holder/payload mutation, provide real IRQ serialization or remove native build
inhibition. Amiberry, physical A1200/AmiGUS, timing, audio and listening remain
unqualified for this provider. The existing exact New/Load document fixtures do
not include this HOST-only provider and retain their separate qualification.


## Retained packet checks before resource calls and cached replies

The same retained-packet observation now runs before clock, ARM, REARM, APPLY,
ACK, CANCEL, ticket quiet, reader quiet, source close and source quiet work. It
also precedes cached ACK/CANCEL and quiet/close replies. An observed mismatch
latches failure, performs no requested resource callback, preserves output
arguments and leaves previous row observations intact. Ordinary numeric and
output-alias admission retains its refusal precedence. PCM and cache payloads
are not scanned, and packet equality is not proof of genuine version ownership.

Restoration of an already-open entry remains owed. `leave` therefore retains its
original callback path even after a precall refusal. The complete post-callback
check still detects the changed packet, retaining restoration uncertainty and
blocking disposal. A second `leave` is refused without another callback. This
change neither skips an owed restoration nor treats it as a quiet certificate.

The new fixture covers ten ready-operation controls and120 stale metadata cases,
plus six valid cached replies and72 stale cached replies. Twelve packet changes
include invalid counts and null descriptor pointers that are never followed.
Positive controls prove each tested callback or cached path was actually ready;
all16 complete independent model cleanup. The192 negative cases preserve all
callback counters, the existing backend lock/token, caller packet and outputs
and previous row observations. Each permits exactly one original restoration
attempt and then retains HOLD. The enclosing genuine source owner retains its
three pins and2304 Chip-cache bytes. The ARM positive control uses a second
synthetic future packet with the same genuine held sources; it is not evidence
of arbitrary-song timing or renderer emission.
