## Finding resolved

Freeze01 used struct assignment to construct byte-beforeimage objects and then compared their entire object representation with `memcmp`. C aggregate assignment need not preserve padding. Consequently a valid unchanged request or publication could spuriously be classified as mutated on another compiler or target.

The six reviewed byte-copy fixes cover the typed request snapshot, CONTROL publication predecessor, successor, first actual post-state and packet, plus retained first predecessor identity. These preserve the representation used by the subsequent mutation checks. Fieldwise key comparisons remain unchanged. This is a portable correctness fix, not a relaxation of failure handling.

## Recursive refusal semantics

Already-bound/nonempty `control_bind` calls can return INVALID before `task_enter`, even when invoked recursively. This is a harmless refusal-only path with no write, callback or acquisition; no functional blocker was identified. Malformed or semantically invalid requests likewise preserve their guards before owner writes. Valid active calls that reach task/fire exclusion detect reentry and fault.

The original new H statement that all “reentry” turns raw0 into uncertainty was too broad. Current comment-only clarification now accurately says mutation or a detected task/fire exclusion fault does so, while refusal-only invalid recursive entries need not fault. The HOST fixture tests genuine diagnostic/fire exclusion reentry, not every refusal-only API call.
